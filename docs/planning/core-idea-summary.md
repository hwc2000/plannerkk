# AI 개인화 플래너 — 핵심 아이디어 정리

> 졸업작품의 중심은 **사용자의 실행 이력과 승인된 기억을 반영해, 계획이 실패해도 다시 실행 가능한 형태로 회복시키는 AI 플래너**다.

## 1. 문제와 차별점

일반 캘린더·투두 앱은 일정을 기록하고 완료 여부만 관리한다. 하지만 계획이 무너진 뒤에는 사용자가 다시 우선순위를 정하고, 실패 원인을 해석하고, 새 계획을 만들어야 한다.

이 서비스는 다음 흐름을 지원한다.

```txt
계획 작성 → 실행 → 성공/실패 체크인 → 원인 기록 → 기억 후보 추출
→ 사용자 승인 → 다음 계획과 회복 코칭에 반영
```

핵심은 단순한 챗봇이나 일정 생성이 아니라,

- 사용자의 실행 방식과 제약을 **누적해서 이해**하고
- AI가 기억을 **임의로 확정하지 않으며**
- 실패한 계획을 버리지 않고 **현실적인 최소 행동으로 복구**한다는 점이다.

## 2. 핵심 기능

### A. 캘린더 기반 계획 관리

- 사용자가 캘린더/오늘 화면에서 직접 일정과 할 일을 입력한다.
- 각 계획에는 우선순위, 예상 시간, 상태(예정/진행/완료/미룸)를 둔다.
- AI는 사용자가 입력한 계획을 대체하는 것이 아니라, 분해·정리·수정하는 보조 역할을 한다.

### B. 맥락형 AI 계획 요청

AI는 독립적인 일반 챗봇 탭보다, 오늘·캘린더·전체 계획 화면에서 필요한 순간 열리는 조율 도구다. 사용자는 자연어로 요청할 수 있다.

```txt
"오늘 계획 너무 많은데 줄여줘"
"이걸 25분 단위로 나눠줘"
"수업 때문에 오후 일정 다시 짜줘"
"계속 미루는데 지금 할 수 있는 최소 행동만 정해줘"
"이번 주 목표들을 마감 위험도 기준으로 다시 조정해줘"
```

AI는 현재 계획, 고정 일정, 프로젝트 마일스톤, 최근 체크인, 승인된 기억을 참고해 **적용 전 검토 가능한 계획 초안 또는 조정안**을 제공한다.

### C. 성공/실패 체크인

계획 카드에서 사용자가 결과를 빠르게 기록한다.

- 완료
- 일부 완료
- 미룸/실패

결과 자체보다 **왜 그런 결과가 났는지**를 남기는 것이 개인화의 근거가 된다.

### D. 승인형 장기기억

AI는 대화나 체크인에서 사용자의 성향·제약·반복 패턴을 발견하면 **기억 후보**만 제안한다.

```txt
기억 후보 예시
- "사용자는 할 일이 많아 보이면 시작을 미루는 경향이 있다."
- "사용자는 25분 단위의 작은 작업에서 실행률이 높다."
- "수업이 있는 날은 오후 계획의 부담을 낮춰야 한다."
```

사용자는 기억 후보를 다음 중 하나로 처리한다.

```txt
[저장] [문구 수정 후 저장] [이번에만 적용] [저장하지 않음]
```

승인된 기억만 이후 계획과 코칭에 반영한다. 사용자는 기억 목록에서 수정·삭제할 수 있다.

### E. 회복 코칭

실패를 질책하지 않고, 남은 시간과 원인을 기준으로 재시작 가능한 계획을 만든다.

```txt
기존 계획: 포트폴리오 전체 수정 (3시간)
실패 원인: 시작 부담이 큼 / 피로함

회복 계획:
1. 10분 — 포트폴리오에서 수정할 페이지 1개 고르기
2. 15분 — 첫 화면의 문장 3개만 수정하기
3. 완료 후 다음 작업을 다시 제안받기
```

## 3. UI 방향: 오늘 + 캘린더 + 전체 계획 + 최소 AI 패널

순수 챗봇 형태가 아니라, **계획을 눈으로 조작하고 여러 목표의 위험도를 비교하는 대시보드**가 중심이다.

```txt
[오늘의 계획 / 캘린더 / 전체 계획]
  ├─ 오늘: 실행 · 완료 · 일부 완료 · 미룸
  ├─ 캘린더: 날짜별 짧은 일정 입력
  ├─ 전체 계획: 프로젝트별 기간 경과 · 실제 달성 · 위험도
  ├─ 빠른 체크인과 기억 관리
  └─ AI에게 계획/조정 요청 버튼

[맥락형 AI 패널]
  └─ 계획 생성/수정, 우선순위 조정, 회복 코칭, 주간 재조율
```

### 첫 계획 생성: 버튼은 필요하지만, ‘자동 생성’ 버튼은 아니다

처음 방문한 사용자는 캘린더가 비어 있으므로 AI와 대화를 시작할 명확한 진입점이 필요하다. 이때 버튼은 계획을 즉시 확정하는 기능이 아니라, 사용자가 목표·제약을 자연어로 말하는 **계획 생성 대화창**을 여는 역할을 한다.

```txt
빈 캘린더 화면

"아직 오늘의 계획이 없어요. 무엇을 해볼까요?"

[AI와 오늘 계획 만들기]   [직접 일정 추가]
```

`AI와 오늘 계획 만들기`를 누르면 채팅/모달이 열리고, 사용자는 계획 자체가 아니라 현재 상황을 말한다.

```txt
사용자: "오늘 저녁 7시까지 졸업작품 기획 정리하고 싶어. 3시부터 5시는 수업이야."
AI: 오늘 가능한 시간을 기준으로 초안을 만들었어요.

[계획 초안 미리보기]
- 17:30–17:50  핵심 기능 3개 정리
- 18:00–18:25  화면 흐름 초안 작성
- 18:35–18:55  팀원 공유용 요약 작성

[이 계획 적용] [수정 요청] [직접 편집]
```

따라서 첫 진입은 **버튼 → 대화 → 계획 초안 → 사용자의 적용 승인** 순서다. 사용자가 이미 계획을 만든 뒤에는 대시보드의 AI 코치 채팅에서 바로 요청할 수 있고, 별도의 ‘계획 생성’ 버튼을 강제하지 않는다.

### 계획 카드의 추천 버튼

각 카드에 긴 입력 폼을 노출하지 말고, 즉시 행동 버튼을 둔다.

```txt
[시작] [완료] [일부 완료] [미룸] [AI에게 조정 요청]
```

`완료`, `일부 완료`, `미룸`을 누르면 작은 체크인 모달을 연다.

### 체크인 모달 예시

#### 미룸/실패 버튼을 눌렀을 때

```txt
오늘 이 계획은 어떻게 됐나요?

( ) 시작하기가 어려웠음
( ) 예상보다 오래 걸렸음
( ) 에너지/집중력이 부족했음
( ) 다른 급한 일이 생김
( ) 계획 자체가 모호했음
( ) 직접 입력

추가 메모 (선택)
[________________________________]

[회복 계획 제안받기]
```

#### 완료/성공 버튼을 눌렀을 때

```txt
완료할 수 있었던 이유가 있나요? (선택)

[ ] 작업이 작게 나뉘어 있었음
[ ] 시간대가 잘 맞았음
[ ] 마감/약속이 동기가 됐음
[ ] 주변 환경이 좋았음
[ ] 직접 입력

추가 메모 (선택)
[________________________________]

[기록 저장]
```

### 체크인 뒤 기억을 제안하는 흐름

모달에서 사용자가 원인을 기록한 뒤, AI가 즉시 기억을 확정하지 않는다.

```txt
체크인 저장
  ↓
AI가 원인/메모/최근 이력을 해석
  ↓
"다음 계획에 반영할 기억을 제안했어요" 배지 표시
  ↓
기억 후보 검토 모달 또는 기억 관리 화면
  ↓
[저장] [수정 후 저장] [이번에만 적용] [거절]
```

이 흐름의 장점:

- 사용자는 긴 채팅을 하지 않아도 성공/실패 데이터를 남길 수 있다.
- 선택지와 짧은 메모를 함께 제공해 입력 부담을 낮춘다.
- AI의 개인화 근거가 사용자에게 보인다.
- 사용자가 민감한 기억의 저장 여부를 통제한다.

## 3-1. 전체 계획: 장기 목표 조율 화면

`오늘`은 실행 화면, `캘린더`는 시간 배치 화면이며, **전체 계획**은 여러 장기 목표를 함께 조율하는 화면이다. 별도의 일반 챗봇 탭을 핵심으로 두지 않는다.

### 프로젝트 모델

사용자는 학업, 자격, 취업, 개인 목표, 행사 등 어떤 종류든 같은 프로젝트 구조로 등록한다.

```txt
프로젝트
- 제목 / 분류 / 중요도
- 시작일 / 마감일
- 예상 작업량과 마일스톤
- 현재 달성률
- 고정 일정과 의존 작업
```

특정 사용자 사례나 과목/자격 이름을 UI·로직에 하드코딩하지 않는다.

### 진도 판단 UI

각 프로젝트 카드에는 최소한 다음을 병렬로 표시한다.

```txt
기간 경과율: 시작일부터 마감일까지의 경과 비율
실제 달성률: 완료된 마일스톤의 가중 진행률
진도 차이: 실제 달성률 - 계획상 기대 진도
```

초기에는 기간 경과율을 비교 기준으로 쓸 수 있지만, 장기적으로는 마일스톤과 예상 작업량으로 만든 **프로젝트별 기대 진도선**을 기준으로 판단한다. 모든 프로젝트가 매일 같은 양으로 진행되지 않기 때문이다.

```txt
[주의 프로젝트]
기간 경과  5 / 20일 · 25%
실제 달성  21%
예상 진도보다 4%p 늦음
```

### 상태와 AI 분기

- **정상(초록):** 목표 진도 이상이거나 현재 가용시간으로 유지 가능
- **주의(주황):** 일부 지연됐지만 이번 주 작업 배분으로 회복 가능
- **조정 필요(빨강):** 현재 계획대로면 마감 위험 또는 선행 작업 미완료
- **시작 전(회색):** 시작일 전이거나 마일스톤/예상 작업량이 아직 없음

AI는 색만 표시하지 않고, 기간·마일스톤·고정 일정·승인된 실행 이력을 근거로 조정안을 **후보**로 제시한다.

```txt
이번 주 재조율
- 가용 시간 내에 회복 가능한 작업 블록 제안
- 과한 날의 작업 이동 또는 분산
- 범위 축소 / 마일스톤 재추정 / 원인 체크인 분기

[적용] [일부만 적용] [수정] [유지]
```

### UI 정보 구조

```txt
오늘        → 오늘 실행과 짧은 상황별 AI 도움
캘린더      → 월간 일정과 날짜별 짧은 계획 입력
전체 계획  → 프로젝트 목록, 진도 비교, 위험도, AI 재조율
기억        → 승인된 개인화 정보와 후보 검토
```

## 4. AI 워크플로 방향

### 기본 방향: 상태 기반 단일 플래너 워크플로

초기에는 여러 에이전트가 자유롭게 대화하는 멀티에이전트보다, 하나의 명확한 워크플로를 사용한다.

```txt
사용자 요청 또는 체크인
  ↓
현재 사용자 컨텍스트 조립
  - 오늘 계획
  - 고정 일정
  - 최근 성공/실패 기록
  - 승인된 기억
  ↓
계획 생성 / 수정 / 회복 코칭 / 기억 후보 추출
  ↓
구조화된 결과 검증
  ↓
계획 저장 또는 기억 후보 제안
  ↓
사용자 승인 후 기억 반영
```

LangGraph는 멀티에이전트 자체를 보여주기 위한 용도보다,

- 계획 생성과 회복의 분기
- 기억 저장 전 사용자 승인 대기
- 승인/거절 뒤의 재개
- 단계별 상태 저장

을 관리하는 워크플로 엔진으로 사용한다.

### 확장 방향: 필요할 때만 역할 분리

기능이 안정된 후에만 다음처럼 역할을 제한적으로 분리할 수 있다.

```txt
Planner 역할: 계획 생성·분해·우선순위 조정
Recovery Coach 역할: 실패 원인 기반 최소 행동 설계
Memory Curator 역할: 기억 후보 제안 및 중복/민감도 점검
```

그러나 첫 구현에서 멀티에이전트를 목표로 하지 않는다. 사용자 경험과 데이터 흐름이 먼저다.

## 5. 개인정보·보안 원칙

AI에게 DB 접근 권한이나 SQL 실행 권한을 주지 않는다.

```txt
Django 서버가 로그인 사용자의 데이터만 조회
→ 필요한 최소 정보만 정제한 컨텍스트로 AI API에 전달
→ AI는 구조화된 계획/기억 후보만 반환
→ 서버가 형식 검증 후 DB에 저장
```

필수 원칙:

- AI는 DB connection string, SQL, 다른 사용자 데이터에 접근할 수 없다.
- 모든 DB 조회/저장은 서버의 로그인 사용자 ID를 기준으로 강제한다.
- 비밀번호, 인증 토큰, 이메일 등 불필요한 개인정보는 AI 컨텍스트에서 제외한다.
- AI가 생성한 내용은 검증된 필드만 저장한다.
- 기억은 AI가 자동 확정하지 않고 사용자의 승인·수정·삭제 권한을 보장한다.

## 6. 졸업작품 핵심 한 줄

> **사용자의 실행 이력과 승인된 장기기억을 바탕으로, 계획 실패 후에도 개인에게 맞는 최소 행동으로 다시 시작하도록 돕는 AI 회복 플래너**
