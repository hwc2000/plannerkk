# 플래너 대화: 기능 고르기(라우팅) → 필요한 정보 꺼내기 → 기능 실행

코드: `server/app/planner_skills.py` (대화 API는 `server/app/planner_chat.py`) · 화면: `src/features/execution/PlannerChat.tsx`

대화 한 번(메시지 하나)을 처리하는 방법이다. 예전에는 LLM 한 번에 프로필·설정·이번 주 작업을 전부 넣고
의도(`none|plan|settings|project_settings`)와 값을 한꺼번에 받았다. 지금은 **먼저 무엇을 할지만 고르고, 그 일에 필요한
정보만 꺼내서** 처리한다. LLM이 매번 읽는 양이 줄고, 기능마다 짧은 지시만 따르면 된다.

## 흐름

```text
메시지 ─▶ ① 기능 고르기 (LLM, planner_route)
           기본 정보만 본다 → 기능 1개 + 꺼낼 정보(lookups)
       ─▶ ② 정보 꺼내기 (코드)
           고른 기능이 늘 쓰는 정보 + ①이 더 필요하다고 한 정보를 저장된 상태에서 계산
       ─▶ ③ 기능 실행 (LLM, planner_<기능>)
           그 기능의 짧은 지시 + 스키마로 답장과 값
       ─▶ ④ 확인 카드 (코드)
           값을 검증해 카드 하나로. 저장은 사용자가 카드를 눌러야 한다
```

- 인사·감사·잡담(`small_talk`)만 ①에서 바로 답하고 끝난다(LLM 1번). 질문은 항상 ③까지 가서 정보를 보고 답한다.
- 기다리는 카드가 있을 때 "응, 그렇게 해 줘"(`confirm`)는 코드가 답하고, 화면이 그 카드의 버튼과 같은 처리를 바로 실행한다(LLM 1번).
- 그 외에는 LLM 2번(① + ③). 숫자 계산·시간 합치기·배치는 모두 코드가 한다.
- 답장 메시지에는 어떤 기능이 답했고 무엇을 봤는지 남는다(`messages[].skill`, `lookups`). 화면에 "계획 조정 · 이번 주 시간표 확인"처럼 보인다.

## 기본 정보 (매번 보는 것)

| 키 | 내용 |
|---|---|
| `today`, `weekday` | 오늘 날짜와 요일 |
| `project` | 이 대화의 프로젝트(제목·목표·기간). 자유 계획이면 null |
| `activeWeek` | 진행 중인 주간 계획의 시작·끝 날짜 |
| `hasAvailability` | 매주 계획할 시간을 정했는지 |
| `waitingCard` | 아직 누르지 않은 카드(반영 안 된 제안)와 그 이름(`about`) |
| `messages`, `message` | 최근 대화 16개, 이번 메시지 |

## 꺼내는 정보 (lookups, 코드가 계산)

| 이름 | 코드 이름 | 내용 |
|---|---|---|
| 이번 주 시간표 | `week` | 요일별 가능한 시간, 고정 일정·비워 둔 시간·캘린더로 빠진 시간, 이 대화 작업 시간, 다른 프로젝트별 작업 시간, 지금 이후 남은 빈 시간, **합계(`totals`, 다른 프로젝트별 합계 포함)** |
| 프로필 | `profile` | 적용 중인 값마다 출처(설문 답 / 이 프로젝트에서 사용자가 정함 / 기록으로 배움 / 시작값), 기본 프로필 값, 생활 방식, 집중이 잘 되는 시간대. 정하지 않은 하루 계획량·시작 행동도 "정하지 않음"으로 넣는다 |
| 이 프로젝트 작업 | `tasks` | 이번 주 이 대화의 계획 목표, 작업의 날짜·시각·완료 여부, 배치 못 한 작업과 이유, 계획에 적용한 근거(`planReasons`, 계획 카드의 근거와 같음) |
| 실행 기록 | `records` | 최근 14일 이 대화의 실행 기록(결과·실제 시간·이유·메모)과 승인을 기다리는 학습 변경. 기록이 없는 작업은 "했는지 모름" |

다른 프로젝트의 **설정**은 어디에도 넣지 않는다(프로젝트 독립). 다른 프로젝트는 이번 주 시간표에 "제목 + 쓴 분"으로만 보인다.
합계를 코드가 넣는 이유: 실제 모델로 확인했을 때 LLM이 분을 더하다 틀린 숫자("총 5시간")를 말한 적이 있다.

## 기능 (skills)

| 기능 | 코드 이름 | 언제 | 늘 꺼내는 정보 | 결과 카드 |
|---|---|---|---|---|
| 답하기 | `answer` | 질문·설명(얼마나, 언제, 왜, 맞아?) | 시간표, 작업 (+①이 고른 프로필·기록) | 없음 |
| 계획 만들기 | `plan_create` | 이번 주 할 일을 새로 계획 | 시간표, 작업 | `plan`: 목표·시작일 + 남은 빈 시간(코드 계산) → 누르면 초안 생성 |
| 계획 조정 | `plan_adjust` | 이미 있는 이번 주 계획 바꾸기: 특정 날짜·시간 비우기, 분량 줄이기·바꾸기 | 시간표, 작업 | `adjust`: 비워 둘 시간(`blockedTimes`) 그리고/또는 다시 짤 목표 → 누르면 시간 비우기(겹친 작업은 코드가 옮김) → 필요하면 이 프로젝트만 재계획 초안 |
| 가능한 시간 바꾸기 | `availability` | 매주 반복되는 계획 시간을 더하거나 빼기 | 시간표 | `settings`: LLM은 말한 시간(요일은 '토' 같은 이름)과 `add/remove/replace`만, 요일 번호와 전체 시간은 코드가 계산. 카드에 더할·뺄 시간 |
| 프로젝트 방식 정하기 | `project_settings` | 이 프로젝트를 하는 방식(25분씩, 하루 1시간 등)을 값으로 직접 말함. 지금 값을 묻는 건 `answer` | 없음(프로필·이전 대화를 보여 주지 않음) | `project_settings`: 이번 메시지에서 말한 값만, 이미 같은 값이면 카드 없음, 규칙에 어긋나면 이유만 |

라우터만 고르는 두 가지: `small_talk`(인사·감사, ①의 답장을 그대로 씀), `confirm`(기다리는 카드를 받아들이는 말, 코드가 답하고 화면이 카드를 적용).

코드가 라우팅을 바로잡는 경우: 자유 계획에서 `project_settings` → `answer`, 진행 중인 주가 없는데 `plan_adjust` → `plan_create`.

## LLM과 코드의 경계

- LLM: 무엇을 원하는지 고르기, 말한 값 뽑기, 답장 쓰기.
- 코드: 정보 계산, 시간 합치기(`availability`), 날짜·시간 검증(이번 주·오늘 이후·8~23시·중복 제거), 카드 만들기, 배치.
- 공통 지시: 바꾸겠다·바꿨다고 말하지 않고 말한 내용을 확인하는 문장만 쓰기, 카드·확인 버튼 이야기는 하지 않기(코드가 붙임), waitingCard는 물을 때만 언급, 숫자는 꺼낸 정보에 있는 것만, 저장된 작업의 날짜·시각은 말해도 되지만 없는 일정은 지어내지 않기.
- 카드 안내는 코드가 쓴다: 카드가 새로 생긴 답장 아래에만 "아래 카드에서 확인을 누르거나 '좋아요'라고 답하시면 적용돼요"를 붙인다. 메시지에는 화면에 보이는 `content`와 모델이 쓴 부분 `reply`를 따로 저장하고, 다음 대화에는 `reply`만 넘긴다(모델이 안내 문장을 따라 하지 않게).
- 카드는 새 카드가 생길 때만 바뀐다. 질문 하나로 지워지지 않고, 다른 종류의 카드로 바뀌면 코드가 "앞의 제안은 이 제안으로 바뀌었어요"라고 말한다.

## 실제 모델 확인 (gpt-4o-mini, 10/15)

- 라우팅 8문장 × 3번 = 24번 모두 맞음: 계획 요청, "금요일 저녁은 약속", "남은 시간 얼마나", "왜 이렇게 계획했어", "토요일 오전 추가", "하루 1시간만", "분량 줄여 줘", "고마워요"(설정 대화 직후).
- 처음 프롬프트에서 틀린 것과 고친 것:
  - 직전 기능을 따라감("남은 시간 얼마나" → 계획 조정, "고마워요" → 프로젝트 방식) → "이번 message만 보고 고른다" + 예시
  - 매주 시간 추가를 전체 교체로 냄(기존 저녁 시간이 사라질 뻔) → `add/remove/replace` + 코드가 합침
  - 계획 카드 없이 "계획을 세울 수 있습니다"로 끝남 → "할 일을 하나라도 말했으면 ready, 시작일 없으면 오늘"
  - 답장에 숫자·요일별 작업을 지어냄 → 숫자는 카드·합계로, 요일별 배치는 말하지 않기
- 브라우저: 계획 → "금요일 저녁은 약속" 카드 → 확인 → "겹친 작업 4개를 빈 시간으로 옮겼어요" → "남은 시간 얼마나" 380분(코드 합계와 같음)

## 실제 모델 확인 (10/19, 23문장 × 3번)

같은 문장(질문 8개, 설정 뒤 "응 그렇게 해 줘"·"좋아 반영해 줘", 매주 시간·분량·하루 계획량, 설정 뒤 질문 5개)을 고치기 전과 후에 보냈다.

| 항목 (69턴) | 4o-mini 전 | 4o-mini 후 | 5.4-mini 후 |
|---|---|---|---|
| 다음 메시지가 기다리던 카드를 지움 | 11 | 0 | 0 |
| "응 해 줘"가 카드 확인으로 감 | 0/6 (앞 기능을 다시 돌리고 또 약속) | 4/6 | 6/6 |
| 라우터가 데이터 없이 혼자 답함 ("오늘 뭐 해야 돼?" 일반론 등) | 14 | 0 | 0 |
| 바꾸겠다는 말투(모델 문장) | 27 | 5 | 10 (대부분 "원하시면 정리해 드릴게요") |
| 카드 없는데 "확인 버튼" 안내 | 7 | 0 | 0 |
| "토요일"이 토요일로 | 0/3 (일요일로 들어감) | 3/3 | 3/3 |
| 말 안 한 설정값을 카드에 옮겨 적음 | 9/9 | 0/9 | 0/9 |
| 질문 라우팅 틀림(확인 말 제외) | 4 | 1 ("고마워" → 계획 조정) | 0 |

- 브라우저(실제 모델): "수요일 저녁은 약속" → 카드 + 코드 안내 → "남은 시간 얼마나?"(카드 유지) → "좋아요" → 시간 비우고 겹친 작업 이동. 지난 작업 "못 했어요" → 복구안(다른 시간으로 옮기기) → 승인 → 계획 반영.
- 같이 찾은 것: 계획 생성이 시간 지정형에서 `doneWhen`에 시작 시각("2026-10-19T20:15")을 쓰고 있었다 → 지시 + 코드 검사(날짜·시각이면 다시 생성, 재시도가 끝나면 "‘제목’ 마치기")
